# Change feature scope

Read the feature, plan, checkpoint, relevant domain docs, implementation and available PRs. Record the exact added, removed and changed requirements in the design; distinguish current shipped behavior from the proposal. Impact-check completed and remaining phases, code, API, schema, invariants, tests, domain docs, dependencies and PR boundaries.

Revise affected future phases and verification, and record follow-up work for completed phases without rewriting history. Correct domain docs only for independently verified current behavior. Update the checkpoint with the delta, impact, blockers and one next action. Surface decisions that materially alter the user's requested direction; honor approval already provided for the change and do not demand new approval for routine choices.
